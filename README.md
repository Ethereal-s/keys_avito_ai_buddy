# AI-buddy — ИИ-наставник для стажёров (прототип)

Кейс Hack&Change 2026 (Авито). Веб-приложение: чат с помощником, чек-лист адаптации, заявки на отсутствие.

**Стек:** Go (net/http) · PostgreSQL · React + TypeScript (Vite) · Docker Compose.
Все данные синтетические, инструкции в базе знаний — **тестовые**, не регламенты Авито.

## Быстрый старт

```bash
.env        # LLM_API_KEY можно оставить пустым 
docker compose up --build
```
Откройте http://localhost:3000.

## Три сценария

1. **Вопросы о команде и инструментах** — поиск по базе знаний (Postgres), ответ с источником. Учитываются права: документ для наставников стажёру не раскрывается; если ответа нет — эскалация к наставнику.
2. **Отгул через сервис отсутствий** — помощник объясняет порядок, разбирает даты («20.11», «с 15 ноября по 16 ноября»), проверяет правила, просит подтверждение, вызывает имитацию сервиса, показывает и сохраняет результат (номер, статус, согласующий).
3. **Этапы адаптации** — чек-лист по этапам со статусами, прогресс и «следующий шаг» (в чате и в панели справа).

Метрики пользы (панель у наставника): число ответов по базе знаний, эскалаций, отказов по правам, созданных заявок, прогресс по шагам.

## LLM (внешний API)

- Сервис: любой OpenAI-совместимый `/chat/completions`.
- Переменные окружения: `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` (задаются в `.env`, секреты в репозиторий не попадают).
- LLM только формулирует ответ по найденной инструкции. Без ключа или при сбое ответом служит текст инструкции — сценарии работают полностью.

## Тесты и покрытие

```bash
docker compose --profile test run --rm tests
```
Запускает Postgres для тестов и `go test` с покрытием `./internal/...`; итог выводится в консоль, отчёт — в `coverage/cover.out` и `coverage/cover.html`.


## Архитектура и интеграции

```
Браузер ── nginx (frontend:3000) ──/api──> Go backend ── PostgreSQL
                                              ├─ AbsenceClient ──> /mock/absence (имитация сервиса отсутствий)
                                              └─ LLM (OpenAI-совместимый API, опционально)
```
- Авторизация и роли в Авито уже существуют; здесь — упрощённая имитация (логин/пароль, токен сессии в БД, роль проверяется на сервере).
- Права: фильтрация знаний по роли, задачи и заявки привязаны к `user_id` из сессии, метрики — только наставнику.
- Подключение реальных сервисов: заменить реализацию `AbsenceClient` (HTTP/MCP-клиент) без изменения сценариев; сценарии описаны контрактами инструментов в `specs/ai-buddy.md`.
- Запросы к LLM и внешним сервисам не блокируют интерфейс: показывается статус «думает…», ошибки выводятся пользователю.

## Структура
`backend/` — Go-сервис, `frontend/` — React-приложение, `specs/` — SDD-спецификации, `.gitflic-ci.yaml` — пайплайн, `docker-compose.yml` — запуск и тесты.
