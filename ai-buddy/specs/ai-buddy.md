# SDD-спецификация AI-buddy

Спецификация поведения агента и его инструментов. Код и тесты написаны по ней.

## Общие правила
- Каждый запрос выполняется от имени авторизованного пользователя; роль берётся из сессии на сервере.
- Все инструкции в базе знаний — ТЕСТОВЫЕ, а не регламенты Авито.
- Недоступные пользователю сведения и операции не раскрываются и не выполняются.
- Любое действие во внешнем сервисе выполняется только после явного подтверждения пользователя.

## Инструменты (контракты, совместимые по форме с MCP-tools)
| Инструмент | Вход | Выход | Права |
|---|---|---|---|
| `kb.search` | вопрос, роль | документ + оценка релевантности | документ виден, если роль ≥ `min_role` |
| `absence.create` | login, from, to | `external_id`, `status`, `approver` | только для самого пользователя |
| `checklist.get` / `checklist.set_status` | user_id, task_id, status | задачи, прогресс, следующий шаг | только свои задачи |

## Сценарий 1. Вопрос о команде и инструментах
- **GIVEN** стажёр авторизован **WHEN** задаёт вопрос, на который есть инструкция **THEN** получает ответ и название источника.
- **WHEN** лучшая найденная инструкция предназначена для наставников **THEN** ответ — отказ без раскрытия содержимого.
- **WHEN** релевантной инструкции нет **THEN** помощник направляет к наставнику (эскалация).
- **WHEN** LLM недоступна или не настроена **THEN** отдаётся текст найденной инструкции.

## Сценарий 2. Отгул через сервис отсутствий
- **WHEN** пользователь спрашивает про отгул без дат **THEN** помощник объясняет порядок и просит даты.
- **WHEN** даты в прошлом, окончание раньше начала или период > 3 дней **THEN** помощник объясняет причину и не создаёт заявку.
- **WHEN** даты пересекаются с активной (не отклонённой) заявкой **THEN** заявка не создаётся: показывается номер существующей.
- **WHEN** вместе с соседними активными заявками получится больше 3 дней подряд **THEN** заявка не создаётся.
- **WHEN** даты корректны **THEN** помощник предлагает действие «Подтвердить заявку».
- **WHEN** пользователь подтверждает **THEN** вызывается сервис отсутствий; результат (номер, статус, согласующий) показывается в чате и сохраняется.
- **GIVEN** заявка в статусе `pending_approval` **WHEN** наставник этого стажёра выбирает «Согласовать»/«Отклонить» **THEN** статус меняется на `approved`/`rejected`, стажёр получает сообщение в чат; чужие и уже обработанные заявки изменить нельзя, стажёр решать не может.
- Отклонённая заявка освобождает даты.
- **WHEN** сервис недоступен **THEN** пользователь видит понятную ошибку, интерфейс не блокируется.

## Сценарий 3. Этапы адаптации и следующий шаг
- Чек-лист состоит из этапов; у задач статусы `todo`, `in_progress`, `done`.
- **WHEN** стажёр спрашивает «что дальше» **THEN** помощник называет прогресс и первую незавершённую задачу.
- **WHEN** стажёр меняет статус задачи **THEN** прогресс обновляется; чужие задачи изменить нельзя.

## Метрики
Эвенты `chat_*`, `leave_created`, `task_*`; сводка доступна только наставнику.
